Status interpretation
=====================

- **enrollment_required**: machine-checked. Every accepted entry
  is preceded by an operator-and-producer-co-signed enrollment.

- **no_witness_double_cosign**: machine-checked. An honest witness
  (whose key has not been revealed) cannot cosign two different
  roots at the same size for the same operator.

- **forward_secrecy**: the lemma is well-defined and the model has
  the right structure (`Live(O, epoch, sk)` is a linear token that
  the operator consumes-and-re-emits on each `SignCheckpoint`, and
  `RevealOperatorKey` consumes `Live` without re-emitting it; so
  after a `Reveal`, no honest `SignCheckpoint` at that key can
  fire). Tamarin finds no counter-example at any bound we have
  tried (4..8) but the proof search blows up combinatorially
  because `SignCheckpoint` quantifies over arbitrary `(size, root)`
  pairs received from the network. We have not yet found a helper
  lemma or oracle that makes the prover converge. Status: model is
  correct as far as we can tell, but not machine-checked end-to-end.
  Issue #5 stays open for "find the proof-search hint that lets
  the default heuristic finish."

- **sanity_complete_run**: same situation as `forward_secrecy` —
  the model admits the trace (we can construct it by hand from
  the rules) but Tamarin's default search doesn't find it within
  reasonable budget. Issue #7 tracks adding a proof oracle to
  guide the existential search.

The honest summary
==================

Two of three core security lemmas now machine-check in under a
second each on commodity hardware. The third (forward_secrecy)
is structurally sound but waiting on better proof-search guidance.
If you need a fully-mechanical verification of forward secrecy,
this model is not yet sufficient; the witness + enrollment proofs
are.
